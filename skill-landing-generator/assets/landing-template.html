本地目录 · 飞书云文档
双向同步

一个命令完成 init / push / pull / status，让本地 Markdown 与飞书文档始终保持同步。基于 lark-cli，支持增量同步与冲突检测。

~ /feishu-sync
$ /feishu-sync init --dir docs --folder https://xxx.feishu.cn/drive/folder/TOKEN › 扫描本地目录 发现 23 个文件，5 个子目录 › 创建文件夹结构 ✔ 完成 › 上传文件 ✔ 23/23 上传成功 › 生成映射文件 ✔ .feishu-sync.json ✔ 初始化完成 · 映射已建立

前置条件

开始使用前，确保以下工具已就绪。全部检查通过后即可一键同步。

lark-cli 已安装并完成认证。运行 lark-cli doctor 确认全部 pass。

drive:drive scope 权限已授权。运行 lark-cli auth check --scope drive:drive 检查。

Python 3 已安装。

终端
# 安装并认证 lark-cli
$ lark-cli doctor
✔ 全部检查通过

# 确认 drive scope
$ lark-cli auth check --scope drive:drive
✔ scope 已授权

# 如缺少 scope，执行
$ lark-cli auth login --scope drive:drive

核心功能

覆盖同步全流程——从首次建立映射到日常增量同步与状态检查。

↕

双向同步

push 推送本地变更到飞书，pull 拉取飞书变更到本地。增量检测，只处理变化的文件。

⟷

冲突检测

status 命令三向对比，自动识别本地改、飞书改、双边改（冲突），标记清晰。

⚡

批量加速

飞书元数据批量查询（每批 200 个），快速定位变更文件，大幅减少 API 调用。

📄

智能文件处理

.md 文件走飞书文档（富文本），其他文件走云盘上传。自动识别文件类型。

📁

目录结构映射

自动在飞书创建与本地一致的文件夹结构，保持层级关系完整。

🔒

SHA256 校验

基于文件哈希检测变更，确保只同步真正修改过的文件，避免无意义覆盖。

同步流程

从初始化到日常使用的四步工作流。

01 init

首次初始化

扫描本地目录，在飞书创建对应文件夹，上传所有文件，生成 .feishu-sync.json 映射文件。

02 push

推送变更

对比本地文件哈希，增量创建新文档、更新已有文档。新目录自动创建飞书文件夹。

03 pull

拉取变更

批量查询飞书元数据，检测修改时间变化，拉取更新后的文档内容到本地。

04 status

查看状态

三向对比显示 → ← ⟷ + - 标记，快速掌握同步状态，发现潜在冲突。

用法示例

常用命令一览。--dir 默认为 docs 目录。

初始化同步 首次
/feishu-sync init \ --dir docs \ --folder https://xxx.feishu.cn/drive/folder/TOKEN → 建立映射，全量上传
推送本地变更 最常用
/feishu-sync push → 增量同步到飞书 # 新文件自动创建 # 已修改文件覆盖更新
拉取飞书变更 拉取
/feishu-sync pull → 拉取飞书最新内容 # .md → docs +fetch # 其他 → drive +download

状态标记

status 命令输出的差异标记说明。

→ 本地改了

待 push 推送到飞书

← 飞书改了

待 pull 拉取到本地

⟷ 双边冲突

需人工合并：先 pull → 合并 → push

+ − 新增 / 删除

本地新增文件或已删除文件
