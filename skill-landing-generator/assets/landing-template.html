前置条件

开始使用前，确保以下工具已就绪。全部检查通过后即可一键同步。

lark-cli 已安装并完成认证。运行 lark-cli doctor 确认全部 pass。

drive:drive scope 权限已授权。运行 lark-cli auth check --scope drive:drive 检查。

Python 3 已安装。

核心功能

覆盖同步全流程——从首次建立映射到日常增量同步与状态检查。

↕

双向同步

push 推送本地变更到飞书，pull 拉取飞书变更到本地。增量检测，只处理变化的文件。

⟷

冲突检测

status 命令三向对比，自动识别本地改、飞书改、双边改（冲突），标记清晰。

⚡

批量加速

飞书元数据批量查询（每批 200 个），快速定位变更文件，大幅减少 API 调用。

📄

智能文件处理

.md 文件走飞书文档（富文本），其他文件走云盘上传。自动识别文件类型。

📁

目录结构映射

自动在飞书创建与本地一致的文件夹结构，保持层级关系完整。

🔒

SHA256 校验

基于文件哈希检测变更，确保只同步真正修改过的文件，避免无意义覆盖。

同步流程

从初始化到日常使用的完整工作流程。

01 scan

扫描本地目录

递归扫描本地目录，收集所有 Markdown 文件和二进制文件，生成完整文件清单。

02 mkdir

创建文件夹结构

在飞书创建与本地一致的文件夹层级结构，保持目录关系完整。

03 upload

上传文件

.md 走飞书文档 API（富文本），其他文件走云盘上传。生成 .feishu-sync.json 映射文件。

04 push

增量推送

对比本地文件 SHA256 哈希，增量创建新文档、更新已有文档。新目录自动创建飞书文件夹。

05 batch

批量检测

通过飞书元数据批量查询（每批 200 个），快速定位远端变更文件，大幅减少 API 调用。

06 pull

拉取变更

检测飞书修改时间变化，同时通过 search 检测飞书新增文件。.md 走 docs +fetch，其他走 drive +download。

07 status

三向对比

显示 → ← ⟷ + - ↓ 标记，三向对比本地与飞书状态，快速掌握同步情况。

08 merge

冲突处理

发现 ⟷ 冲突标记时，先 pull 保留飞书版本，手动合并内容，再 push 推送合并结果。

用法示例

全部命令与典型场景。--dir 默认为 docs 目录。

初始化同步 首次
/feishu-sync init \ --dir docs \ --folder https://xxx.feishu.cn/drive/folder/TOKEN → 建立映射，全量上传
推送本地变更 最常用
/feishu-sync push → 增量同步到飞书 # 新文件自动创建 # 已修改文件覆盖更新
拉取飞书变更 拉取
/feishu-sync pull → 拉取飞书最新内容 # .md → docs +fetch # 其他 → drive +download # 自动检测飞书新增文件
查看同步状态 状态
/feishu-sync status → 三向对比同步状态 # → 本地改了 # ← 飞书改了 # ⟷ 双边冲突
指定目录推送 进阶
/feishu-sync push --dir my-notes → 同步指定目录到飞书 # 适用于多目录场景 # 需已对该目录执行过 init
指定目录拉取 进阶
/feishu-sync pull --dir my-notes → 拉取指定目录的飞书变更 # 检测该目录的远端修改 # 同时拉取飞书新增文件
指定目录状态 进阶
/feishu-sync status --dir my-notes → 查看指定目录同步状态 # 检查特定目录的差异 # 了解哪些文件需要处理
冲突解决流程 冲突
# 发现 ⟷ 冲突标记时 /feishu-sync pull → 先拉取，保留飞书版本 # 手动合并本地与飞书内容 /feishu-sync push → 推送合并后的结果

状态标记

status 命令输出的差异标记说明。

→ 本地改了

待 push 推送到飞书

← 飞书改了

待 pull 拉取到本地

⟷ 双边冲突

需人工合并：先 pull → 合并 → push

+ − 新增 / 删除

本地新增文件或已删除文件
