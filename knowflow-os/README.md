# KnowFlow OS

AI 原生知识管理与内容运营系统，面向创作者、品牌和内容团队。

## 核心循环

```
信息收集 → 知识归档 → 选题生成 → 内容生产 → 多渠道分发 → 数据复盘 → IP/品牌资产沉淀
```

核心原则：知识按资产归类，内容按场景生产，分发按渠道管理。

## 功能特性

- **项目初始化**：一键创建完整的 KnowFlow OS 目录结构
- **知识导入与分类**：将零散素材分类为可复用的知识资产
- **选题生成**：从知识资产中提取内容选题，评估相关性和传播潜力
- **渠道内容生产**：生成小红书、公众号、视频脚本、PPT 等平台专属内容
- **跨渠道适配**：同一内容改写为不同渠道的版本
- **发布与复盘**：管理发布流程、记录和分析数据

## 目录结构

```
project-root/
├── 00-inbox/              # 收件箱：所有新素材入口
├── 01-knowledge-base/     # 知识库：分类存储知识资产
│   ├── brand/             # 品牌定位
│   ├── products/          # 产品介绍
│   ├── courses/           # 课程体系
│   ├── people/            # 团队/人物
│   ├── cases/             # 案例（默认匿名）
│   ├── faq/               # 常见问题
│   ├── operations/        # 运营数据
│   ├── training/          # 培训资料
│   ├── research/          # 行业研究
│   └── media-assets/      # 图片视频素材
├── 02-scenarios/          # 场景：内容生产场景配置
├── 03-topic-pool/         # 选题池：pending/approved/in-progress/published/archived
├── 04-content-factory/    # 内容工厂：草稿/审核中/已通过/已驳回
├── 05-publish-center/     # 发布中心：排期/记录
├── 06-review/             # 复盘：内容复盘/渠道复盘/月度报告
└── 07-ip-assets/          # IP 资产：品牌识别/ signature 内容/内容系列
```

## 使用方法

直接对 Claude 说：

```
"初始化 KnowFlow OS"
"导入这些素材到知识库"
"基于这些知识资产生成选题"
"写一篇小红书"
"把这个内容改成公众号版本"
"准备发布"
"复盘这篇内容的数据"
```

## 内容渠道支持

| 渠道 | 格式 | 风格 |
|------|------|------|
| 小红书 | 500-1000 字 | 轻松、emoji 丰富 |
| 公众号 | 1000-3000 字 | 结构化、有深度 |
| 朋友圈 | 100-300 字 | 轻松、互动性强 |
| 视频脚本 | 时长驱动 | 口语化、有钩子 |
| PPT | 幻灯片 | 视觉化、要点式 |

## 核心规则

1. 原始素材永不删除、不覆盖
2. 所有素材必须经过 `00-inbox/` 入口
3. 知识资产存储在 `01-knowledge-base/`，场景在 `02-scenarios/`
4. 同一知识资产可被多个场景复用
5. 不同渠道必须生成不同内容版本
6. 案例默认匿名处理
7. 内容生成时必须注明引用了哪些知识资产

## 高阶使用技巧

### 飞书同步 + 评论协作

结合 [feishu-sync](../feishu-sync/) 将整个 KnowFlow OS 目录同步到飞书：

1. **同步到飞书**：`init` 后，本地编辑的内容通过 `push` 推送到飞书文档
2. **飞书阅读与修改**：在手机上用飞书阅读知识资产、批注选题卡片
3. **评论驱动优化**：在飞书文档里添加评论（如"这段太啰嗦"、"加点数据"），AI 读取评论后自动优化内容
4. **拉取更新**：飞书修改后通过 `pull` 同步回本地

这样就实现了"看飞书文档、写评论 → AI 自动改内容"的异步协作流。

### GitHub 全空间备份

整个 KnowFlow OS 就是一个 Git 仓库：

- 换电脑时 `git clone` 即可恢复完整工作空间
- 知识资产、选题池、内容草稿全部版本可控
- 可配合 GitHub Actions 实现自动备份或发布

### 不限 Agent，灵活切换

KnowFlow OS 是一套基于文件系统的内容管理 harness，不绑定任何特定 AI：

- **Claude Code** → 深度编辑、批量处理
- **Cursor / Copilot** → 代码化内容生成
- **Claude.ai / ChatGPT** → 快速脑暴、灵感记录
- **Codex** → 生成图片并自动发布

不同 Agent 用同一套目录结构协作，互不干扰。

### Codex 图片生成 + 自动发小红书

如果使用 Codex，可以打通"图片生成 → 自动发布"的链路：

1. 在 `04-content-factory/` 生成小红书文案
2. 用 Codex 生成配图（基于文案内容或品牌风格）
3. 保存图片到 `media-assets/`
4. 调用 feishu-send 或直接对接小红书 API 自动发布

实现"一句话选题 → 成品内容"的全自动流水线。
